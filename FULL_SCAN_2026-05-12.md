## 🔴 الفجوة 1 — Dimensional / OLAP Reporting (Real-Time HANA-style)

**ما هو موجود:** `bi-cube-engine`, `pivot-engine`, `report-builder-engine`, BiKpiDefinition, BiWidget.
**ما هو ناقص:** Materialized cube refresh schedules، Pre-aggregated fact tables (Sales Fact, Inventory Fact, GL Fact)، Drill-back to transaction، Excel pivot connectivity (XMLA/OData)، Multi-dimensional KPI تعريف بـ MDX-like.

### البرومنت الجاهز
```
أنشئ محرك OLAP يقرأ من جداول transactional ويبني facts متعددة الأبعاد:
- FactSales (date, customer, product, branch, salesman, channel, qty, amount, cost, margin)
- FactGL (date, account, costCenter, profitCenter, segment, dr, cr)
- FactInventory (date, product, warehouse, bin, batch, lot, qty, value)
- FactProcurement (date, vendor, product, branch, qty, amount, lead_time_days)
- FactHR (date, employee, dept, hours, cost)

استخدم Materialized Views في Postgres مع refresh schedule:
- realtime (continuous): لـ FactGL و FactSales
- hourly: لـ FactInventory و FactProcurement
- nightly: لـ FactHR

أنشئ صفحة /reports/cube تسمح:
- Drag-and-drop dimensions/measures (مثل Excel pivot)
- Drill-down → Drill-back to source document
- Save view as KPI tile
- Export to Excel via OData feed
- WebSocket live refresh

استخدم:
- PostgreSQL MATERIALIZED VIEW + pg_cron
- tanstack/react-table للـ pivot UI
- OData v4 endpoint /api/odata/Sales لربط Excel/PowerBI
```

## 🔴 الفجوة 2 — Predictive Inventory & Demand Forecasting (Probabilistic)

**ما هو موجود:** `demand-sensing-engine`, `sales-forecast-engine`, `DemandForecast` model.
**ما هو ناقص:** Probabilistic forecasting (P50/P90/P99)، Promotion/event uplift، Cannibalization، Multi-echelon network optimization، Safety stock dynamic بـ service-level target، Newsvendor model للسلع القصيرة العمر.

### البرومنت
```
أنشئ DemandForecastEngine v2 يستخدم:
- Prophet / NeuralProphet عبر Python microservice (FastAPI)
- Inputs: 36-month sales history per (product, warehouse), promotional calendar, holidays, weather
- Outputs: forecast_p50, forecast_p90, forecast_p99, lower_bound, upper_bound, components (trend, seasonality, holidays)

أضف جدول DemandForecastV2:
- product_id, warehouse_id, forecast_date, horizon_days
- p50, p90, p99 (Decimal 15,4)
- model_version, accuracy_mape (last 4 weeks)

أنشئ ReorderEngine v2:
- safety_stock = (p99 - p50) × lead_time_factor
- reorder_point = forecast_during_LT + safety_stock
```

## 🟠 الفجوة 13 — Embedded Analytics + Anomaly Detection (AI)

**ما هو موجود:** `ai-cfo-engine` (CFO Insights)، `ai-auditor` API folder، `fraud-ai` report، `ai-bank`.
**ما هو ناقص:** Real-time anomaly detection على transactions (Benford's law, GL outliers، duplicate vendor invoices، ghost employees، unusual approval patterns)، AI explanation لكل anomaly، Auto-create audit finding.

### البرومنت
```
أنشئ /admin/anomaly-detection:

Detectors:
1. Benford's Law على Journal Lines (first digit distribution)
2. Duplicate vendor invoices (fuzzy match على vendor + amount + date ±5 days)
3. Round-number bias (amounts ending in 000)
4. After-hours postings (JE created 8pm-6am Riyadh time)
5. Same-user post+approve (SoD violation)
6. Ghost employees (no attendance + no email + paycheck)
7. Velocity (vendor with sudden 10× transactions)
8. Banking changes (vendor bank account changed twice in 30 days)
9. Manual journal to control accounts (RECEIVABLES, PAYABLES, INVENTORY)
10. Negative inventory at month-end

Engine:
- anomaly-detection-engine.ts:
  - daily cron run all detectors
  - score 0-100
  - if score > threshold → AuditFinding auto-create

AI:
- For each finding, LLM explains in plain Arabic why suspicious
- Suggest action: review | reverse | accept

UI:
- /admin/anomalies: heatmap + list of recent findings
- Click → drill-down → LLM explanation + suggested action
- Workflow: review → resolve (with reason) or escalate
```
