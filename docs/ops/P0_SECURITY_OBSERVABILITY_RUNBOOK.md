# دليل تشغيل أدوات الأمان والمراقبة والنسخ الاحتياطي (P0 Security & Observability Runbook)
## Nama Invest SaaS ERP - Operations & Security Runbook

يوفر هذا الدليل التعليمات والسياسات الخاصة بتشغيل ومراقبة أدوات الأمان والنسخ الاحتياطي ومسح سجلات PM2 على البيئة التشغيلية بأمان تام وقراءة فقط:

---

## 1. الأدوات المتوفرة وكيفية تشغيلها (Available Tools)

### أ. تقرير تغطية النسخ الاحتياطي (Backup Coverage Report)
* **الأمر:**
  ```bash
  node scripts/ops/backup-coverage-report.js
  ```
* **الوصف:** يقوم بالاستعلام التلقائي عن كافة قواعد البيانات النشطة التي تطابق النمط `*_db` على خادم PostgreSQL، ومقارنتها بآخر ملفات نسخ احتياطي `.backup` مسجلة في المجلد المخصص على خادم Hetzner، ثم إخراج تقرير بالنسبة المئوية للتغطية وقواعد البيانات المفقودة.

### ب. فحص صحة النظام العام (Runtime Health Report)
* **الأمر:**
  ```bash
  node scripts/ops/runtime-health-report.js
  ```
* **الوصف:** يقوم بإرسال طلبات فحص صحية سريعة وقراءة الرؤوس (Headers) للروابط الرئيسية والفرعية، والتحقق التلقائي من أن الروابط الحساسة (مثل approve API) معزولة وترجع حالة `401 Unauthorized` (Fail-Closed).

### ج. مسح سجلات PM2 والبحث عن الأخطاء (PM2 Log Scanner)
* **الأمر:**
  ```bash
  node scripts/ops/pm2-log-health-scan.js
  ```
* **الوصف:** جلب آخر 200 سطر من سجلات العمليات الأربع النشطة في PM2، وتحليلها للبحث عن أي أخطاء من نوع (Prisma, TypeError, 500, unhandledRejection) مع تعمية كاملة للأسرار قبل طباعتها في المخرجات.

---

## 2. معالجة وتجاوز المشاكل ورصد الأخطاء (Incident Handling)

### أ. في حال رصد فجوة في تغطية النسخ الاحتياطي (Backup Coverage Gap)
إذا أظهر تقرير التغطية وجود قواعد بيانات مفقودة (`missingDatabases`):
1. قم بفتح ملف `server-backup.sh` على الخادم.
2. قم بإضافة أسماء قواعد البيانات المفقودة يدوياً تحت قسم النسخ الاحتياطي، أو قم بترقية السكربت للدوران التلقائي على كافة القواعد المكتشفة بالنمط `*_db`.
3. لا تقم بحذف أي نسخ احتياطية قديمة يدوياً.

### ب. في حال رصد أسرار غير معقمة في السجلات (Secret Detection)
إذا أظهر الفاحص وجود أسرار نشطة (`secretsDetected: true`):
1. قم بإيقاف أو إعادة تحميل الخدمة المتأثرة فوراً.
2. ابحث عن السجل أو المتغير الذي يطبع سر البيئة أو كلمة المرور وقم بحذف جملة الطباعة أو استخدام مكتبة التعمية `maskSecrets`.
3. قم بتدوير (Rotate) كلمة السر أو المفتاح الذي تسرب لضمان السلامة الأمنية.

### ج. تصعيد الحوادث (Escalation Path)
عند رصد أي من الحالات التالية:
* كراش أو خطأ PM2 متكرر (Restart loop).
* تسريب صريح لروابط قاعدة البيانات DATABASE_URL.
* تداخل بين بيانات مستأجرين مختلفين.
يجب فوراً تصعيد المشكلة إلى الفريق الأمني وفصل خادم الـ VPS مؤقتاً لحين معالجة الثغرة.

---

## 3. قيود وسياسات الاستخدام (Strict Read-Only Enforcement)
* يمنع منعاً باتاً تعديل أو إضافة أي معايير أو معاملات كتابة داخل هذه الأدوات.
* لا يسمح باستدعاء عمليات التراجع (Restore) لقواعد البيانات تلقائياً أو عبر الـ AI.
* تظل البيئة والـ `.env` محمية ومقيدة ويحظر تصديرها أو كشف قيمها.
