# دليل النسخ الاحتياطي واستعادة الكوارث (Backup & Disaster Recovery Runbook)
## Nama Invest SaaS ERP - Backup & DR SOP

يوفر هذا المستند الدليل التشغيلي القياسي لإدارة النسخ الاحتياطي واختبارات استعادة الكوارث بأمان تام.

---

## 1. العمليات الروتينية والمراقبة (Routine Operations)

### أ. اكتشاف قواعد بيانات المستأجرين (Tenant DB Discovery)
* لتحديد القواعد المفتوحة والنشطة ديناميكياً:
  ```bash
  node scripts/ops/discover-tenant-databases.js
  ```
  *يجب التحقق من مطابقة القواعد المكتشفة مع لوحة مستأجري SaaS.*

### ب. التحقق من تغطية النسخ الاحتياطي (Backup Coverage Verification)
* لمعرفة أي قواعد بيانات مستثناة من النسخ الاحتياطي التلقائي:
  ```bash
  node scripts/ops/backup-verify-coverage.js
  ```
  *في حال وجود فجوة (GAP_DETECTED)، يرجى مراجعة القسم 3.*

### ج. توليد بيان النسخ الاحتياطي الأخير (Backup Manifest)
* لجلب أسماء وأحجام الملفات المنسوخة بآخر تاريخ:
  ```bash
  node scripts/ops/backup-manifest-generate.js
  ```

### د. فحص سلامة الملفات عبر SHA256 (Checksum Verification)
* للتحقق من سلامة الأرشيفات وعدم تلفها:
  ```bash
  node scripts/ops/backup-checksum-report.js
  ```

---

## 2. إجراءات اختبارات الاستعادة الجافة (Restore Dry-Run Plan)

للقيام باختبار استعادة دوري للتحقق من سلامة ملفات النسخ المأخوذة:

### ⚠️ قاعدة ذهبية أمنية صارمة:
**يحظر تماماً تشغيل أي أمر استعادة (pg_restore / createdb / dropdb) مباشرة على خوادم الإنتاج (Production VPS).**
يتم إجراء كافة الاختبارات ببيئة معزولة بالكامل (Local or Isolated Staging).

### خطوات الاستعادة الاختيارية الجافة:
1. قم بطلب خطة الاستعادة عبر الأداة:
   ```bash
   node scripts/ops/dr-restore-dry-run-plan.js
   ```
2. قم بتحميل الملفات المحددة بالخطة إلى خادم staging.
3. قم بإنشاء قواعد بيانات اختبارية مضاف إليها لاحقة `_test` لتجنب الكتابة العرضية.
4. نفذ عملية الاستعادة وتأكد من اكتمال الجداول (User, TenantAccount) دون أخطاء.
5. قم بتنظيف البيئة وحذف قواعد البيانات المؤقتة بعد انتهاء الفحص.

---

## 3. التعامل مع المشاكل وتصعيد الحوادث (Incident Handling)

### أ. في حال وجود قاعدة بيانات مفقودة من النسخ الاحتياطي (Missing Backup Database)
1. قم بتصنيف المشكلة كـ **Incident - Medium Priority**.
2. تواصل مع مسؤول النظام لإدراج اسم قاعدة البيانات المكتشفة حديثاً في إعدادات تدوير النسخ الاحتياطي التلقائي بالسيرفر.
3. قم بتشغيل عملية النسخ الاحتياطي التلقائي يدوياً للتأكد من شمولها فوراً.

### ب. في حال فشل تطابق SHA256 (Checksum Mismatch)
1. قم بتصنيف المشكلة كـ **Incident - High Priority**.
2. يعتبر الأرشيف تالفاً ومرفوضاً للاستعادة.
3. قم بإلغاء التنبيه وإعادة تشغيل عملية النسخ الاحتياطي (pg_dump) مجدداً للقاعدة المتأثرة.
4. تحقق من المساحة المتاحة بالقرص الصلب بالخادم.

### ج. تصعيد الحوادث (Escalation)
عند رصد تلف أو فقد في قواعد البيانات الأساسية أو الشك في وجود تسريب، قم بالتصعيد فوراً لقنوات الدعم الأمني وفصل الخادم الخارجي عن العمل مؤقتاً لحماية سلامة isolations.
