## السيناريو

عامل باكستاني جديد في الشركة:

1. الـ HR يفتحُ له حساب employee portal
2. Settings → Language → اختر "اردو"
3. الـ UI كامل ينتقل للأوردو (تبقى الأرقام عربية فقط)
4. عامل يفتح payslip → يفهم كل التفاصيل بلغته
5. لو وصل لشاشة لم تُترجم بعد → fallback لـ English
6. الترجمات الناقصة تظهر في `tmp/i18n-report.md` → translator يعمل عليها لاحقاً

PR من مطور جديد يضيف زر بـ Arabic فقط (نسي English):
1. CI يكتشف
2. PR يفشل ❌
3. Reviewer يقترح: `استخدم _t('عربي', 'English')`
4. Developer يصلح → PR يمر ✅

## Data Flow

```
[Scan flow]
Developer pushes PR
   ↓
.github/workflows/i18n.yml
   ↓
scripts/i18n-scan.ts
   ↓
Parse all .tsx files (AST):
   - find t('key.name')
   - find _t('عربي', 'English')
   - find useTranslation hook usage
   ↓
Compare against src/locales/*.json
   ↓
Generate report:
   - missing keys per locale
   - unused keys
   - duplicate translations
   ↓
If missing > 0 → exit 1 (PR fails)
Else → comment on PR with stats

[Runtime flow]
User clicks Language switcher → 'ur'
   ↓
Cookie set: NEXT_LOCALE=ur
   ↓
Next.js reloads with locale=ur
   ↓
src/lib/i18n.tsx loads src/locales/ur.json
   ↓
Component uses _t('عربي', 'English'):
   if (lang === 'ar') return 'عربي'
   if (lang === 'en') return 'English'
   else: lookup full translation table
   ↓
Falls back to en if ur missing
Falls back to key itself if all missing
   ↓
Renders in selected language

[Translation workflow]
PM exports keys to Lokalise:
   npm run i18n:export-lokalise
   ↓
Translator opens Lokalise web UI
   ↓
Sees ar + en + context + screenshot
   ↓
Adds Urdu/Hindi/Filipino translation
   ↓
PM imports back:
   npm run i18n:import-lokalise
   ↓
src/locales/ur.json updated
   ↓
PR created automatically
```
