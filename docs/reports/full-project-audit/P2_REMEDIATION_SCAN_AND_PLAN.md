### 🔐 ISS-05: غياب التحقق من جلسة الصندوق المفتوحة PosSession في نهايات POS

### 📈 ISS-07: تحميل كامل كشوفات دفتر الأستاذ العام دفعة واحدة وتسييل payloads ضخمة بدون pagination

### 🛡️ ISS-08: غياب التحقق المعمق من نوع الملف المرفوع داخل /api/upload
- **الحالة**: تم المسح والتحليل بنجاح.

## 3. Root Cause Analysis (تحليل الأسباب الجذرية)

### 🛠️ ISS-04: Manufacturing BOM N+1 Queries
* **الملفات المحتملة**:
  - [bom-engine.ts](file:///d:/namasoft9-3-main/src/lib/bom-engine.ts)
  - [route.ts](file:///d:/namasoft9-3-main/src/app/api/manufacturing/bom/route.ts)
* **سبب المشكلة**: استخدام معالجة تعاودية خطية في دالة `explode` داخل `bom-engine.ts`؛ حيث يتم الاستعلام عن المكونات كعناصر مفردة داخل حلقة تكرارية بدلاً من تجميعها دفعة واحدة واستدعاء `findMany` باستعمال معامل الـ `in` أو استخدام منطق الـ CTE المتقدم.
* **المخاطر**:
  - بطء استجابة الخادم عند تفجير شجرة BOM عميقة أو معقدة.
  - إرهاق خادم قاعدة البيانات بكثرة الاتصالات والـ roundtrips.
* **نطاق الإصلاح المقترح**: إعادة هيكلة دالة `BOMEngine.explode` لتقوم بجمع تفاصيل كافة المكونات بالاستعلام المتجمع بضربة واحدة، أو تفعيل آلية تخزين مؤقت للـ BOMs المصادق عليها والجاهزة في كاش Redis.

### 🛠️ ISS-05: POS Session Checking
* **الملفات المحتملة**:
  - [route.ts](file:///d:/namasoft9-3-main/src/app/api/pos/checkout/route.ts)
  - [pos-session-engine.ts](file:///d:/namasoft9-3-main/src/lib/pos-session-engine.ts)
* **سبب المشكلة**: واجهة الدفع تعتمد على صلاحيات المستخدم فقط دون إلزام التحقق من حالة صندوق الوردية المالي المفتوح `PosSession` لهذا المستخدم والفرع وجلب معرف الوردية لتضمينه في الفاتورة والترحيل المالي.
* **المخاطر**:
  - فروقات مالية عشوائية في الصناديق.
  - عدم إمكانية مطابقة مبيعات الكاشير بالرصيد الافتتاحي والختامي وعجز تسوية فروق الورديات.
* **نطاق الإصلاح المقترح**: تضمين فحص إجباري في واجهة `checkout` يستعلم عن وجود جلسة وردية مفتوحة `PosSession.status === 'OPEN'` للكاشير والفرع، ورفض الفاتورة في حالة غيابها برمز استجابة 400.

### 🛠️ ISS-06: Cashier Mobile RTL/UI Text Clipping
* **الملفات المحتملة**:
  - [page.tsx](file:///d:/namasoft9-3-main/src/app/(dashboard)/pos/page.tsx)
  - [page.tsx](file:///d:/namasoft9-3-main/src/app/(dashboard)/restaurant-pos/page.tsx)
* **سبب المشكلة**: استخدام هوامش وعروض ثابتة وحاويات غير مرنة لا تتكيف لغوياً مع اتجاه الكتابة العربي (RTL) ولا تطبق الالتفاف المناسب لبعض الكلمات العربية الطويلة.
* **المخاطر**:
  - قص النصوص المالية الحساسة أو أرقام الفواتير على الشاشات المحمولة.
  - صعوبة التفاعل من قبل الكاشير ومخاطر حدوث أخطاء إدخال يدوي.
* **نطاق الإصلاح المقترح**: تحديث وتعديل الهوامش وفئات Tailwind CSS التجاوبية لتفعيل `text-wrap` وصيغ الأبعاد النسبية مع خطوط منسقة ومتحركة مرنة.

### 🛠️ ISS-07: General Ledger Pagination Gaps
* **الملفات المحتملة**:
  - [route.ts](file:///d:/namasoft9-3-main/src/app/api/reports/[type]/route.ts)
  - [route.ts](file:///d:/namasoft9-3-main/src/app/api/reports/dimensional-gl/route.ts)
* **سبب المشكلة**: جلب البيانات في نهايات تقارير المبيعات والمشتريات والمصروفات والأستاذ البُعدي تعتمد على جلب إجمالي بدون معايير ترقيم وتصفية متقدمة، أو سقف محدد مسبقاً بـ `take: 100` أو `take: 500`.
* **المخاطر**:
  - استهلاك مفرط للذاكرة العشوائية للـ Node.js عند جلب تقارير تحتوي على آلاف السجلات.
  - بطء استجابة الشبكة (Network overhead) أو سقوط الخادم بسبب Out-of-Memory.
* **نطاق الإصلاح المقترح**: استخلاص معاملات `page` و `limit` و `cursor` من الـ `searchParams` في نهايات التقارير الطرفية وتطبيق الـ dynamic pagination في Prisma بمرونة مطلقة.

### 🛠️ ISS-08: File Upload Magic-Bytes Bypass
* **الملفات المحتملة**:
  - [route.ts](file:///d:/namasoft9-3-main/src/app/api/upload/route.ts)
* **سبب المشكلة**: تعتمد نهاية الرفع الطرفية كلياً على حقل `file.type` المرسل من الطلب لفحص نوع الملف، بالإضافة لاستخلاص الامتداد مباشرة من اسم الملف المدخل دون قراءة فيزيائية لمحتويات الملف.
* **المخاطر**:
  - تمكين المهاجمين من رفع نصوص برمجية (PHP, JS, Shell scripts) أو ملفات تنفيذية خبيثة عبر التلاعب بالـ MIME-type في الطلب.
* **نطاق الإصلاح المقترح**: قراءة أول بايتات مصفوفة من البافر للملف المرفوع لتحديد الرقم السحري الموثق (مثل `89 50 4E 47` لملفات PNG) ورفض الملف بالكامل فوراً عند عدم تطابق بايتات الملف الفيزيائية مع النوع المزعوم.

- **Zero DB Structural Changes**: لن يتم إجراء أي تعديل على الجداول أو استخدام `prisma db push` أو `SQL migrations` لتجنب مخاطر فقد البيانات أو تدمير الامتثال المحاسبي.
