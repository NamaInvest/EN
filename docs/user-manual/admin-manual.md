# Admin User Manual — Namasoft ERP

> **آخر تحديث:** 2026-05-10
> **الجمهور:** Tenant admins, accounting admins, HR admins.

---

## 1. الإعداد الأول (First-Run Wizard)

عند تسجيل اشتراك جديد، يأخذك النظام عبر:

1. **معلومات المنشأة** — الاسم، الرقم الضريبي (VAT)، رقم السجل التجاري، عنوان الفروع.
2. **الفرع الرئيسي** — البلد (المملكة العربية السعودية)، العملة (SAR)، المنطقة الزمنية (Asia/Riyadh).
3. **شجرة الحسابات** — اختر قالب SOCPA الجاهز أو ارفع شجرتك الخاصة.
4. **الفترة المالية** — تاريخ بداية السنة المالية (افتراضي: 1 يناير).
5. **الضرائب** — VAT 15% مفعّلة افتراضياً، أضف أكواد أخرى عند الحاجة.
6. **المستخدمون** — أنشئ حسابات الموظفين وعيّن الأدوار.
7. **التكامل** — ZATCA certificate upload (Phase 2)، GOSI، WPS، البنوك.

## 3. إدارة المستخدمين والأدوار

### 3.1 إنشاء مستخدم جديد
- **Settings → Users → New User**
- أدخل: البريد، الاسم، الدور.
- يتلقى المستخدم رابط دعوة بالبريد.

### 3.2 الأدوار الافتراضية

| الدور | الصلاحيات |
|------|----------|
| `tenant_admin` | كل شيء (افتراضياً صاحب الاشتراك) |
| `accounting_admin` | محاسبة + تقارير + قراءة مبيعات/مشتريات |
| `sales_manager` | كل شيء في المبيعات + تقارير المبيعات |
| `cashier` | POS فقط |
| `hr_admin` | HR + Payroll |
| `read_only_auditor` | قراءة فقط (للمراجع الخارجي) |

### 3.3 أدوار مخصصة (Phase 2)
- يمكن إنشاء أدوار جديدة بصلاحيات محددة من **Settings → Roles**.

## 4. شجرة الحسابات

- **Accounting → Chart of Accounts**
- التصنيف: 1xxx Assets, 2xxx Liabilities, 3xxx Equity, 4xxx Revenue, 5xxx Expenses
- خصائص الحساب:
  - **Postable** — هل يمكن الترحيل عليه مباشرة؟
  - **Control** — حساب رقابي (مثل Receivables) — لا يقبل قيد يدوي
  - **Currency** — العملة الأساسية للحساب
  - **Tax Code** — الكود الضريبي الافتراضي
- لا يمكن حذف حساب له حركات؛ يمكن فقط تعطيله (`active = false`).

## 5. الفواتير (Sales Invoices)

### 5.1 إنشاء فاتورة
1. **Sales → Invoices → New**
2. اختر العميل (أو أنشئ عميلاً جديداً).
3. أضف بنود الفاتورة:
   - الصنف، الكمية، السعر، نسبة الضريبة، الخصم.
4. التواريخ: تاريخ الإصدار، تاريخ الاستحقاق.
5. **Save Draft** أو **Save & Post**.

### 5.2 الترحيل (Posting)
- ترحيل الفاتورة يولّد قيد محاسبي تلقائياً:
  ```
  Dr Receivables   1,150
      Cr Sales            1,000
      Cr VAT Output         150
  ```
- بعد الترحيل، يتم إرسالها لـ ZATCA تلقائياً (Phase 2 B2B).
- **لا يمكن تعديل** فاتورة مرحّلة — أصدر إشعار دائن (Credit Note) بدلاً.

### 5.3 حالات ZATCA
- 🕐 `PENDING` — في الـ queue للإرسال
- ✅ `CLEARED` — تم القبول، QR متوفر للطباعة
- ❌ `REJECTED` — راجع رسائل الخطأ، أصلح، وأعد الإرسال

## 6. POS — نقطة البيع

### 6.1 فتح وردية
1. سجّل دخول كـ كاشير على شاشة POS.
2. أدخل **Starting Float** (المبلغ النقدي الأولي).
3. ابدأ البيع.

### 6.2 إجراء عملية بيع
1. اختر الأصناف من الشبكة أو ابحث.
2. أضف الكميات.
3. اختر طريقة الدفع: نقد / مدى / فيزا / تحويل / هيبر باي.
4. اطبع الإيصال (تلقائياً يحتوي ZATCA QR).

### 6.3 إغلاق الوردية
1. **Close Session**.
2. أدخل المبلغ النقدي المعدود.
3. النظام يحسب الفرق (Variance) ويسجّله في حساب "Cash Over/Short".

## 7. الرواتب

### 7.1 إعداد موظف
1. **HR → Employees → New**
2. أدخل: الاسم، الإقامة/الهوية، الجنسية، تاريخ التعيين.
3. أضف **عقد العمل**: الراتب الأساسي، البدلات، تاريخ بدء الاستحقاق.
4. **Saudi national?** — يحدّد تطبيق GOSI + SANED بشكل مختلف.

### 7.2 تشغيل دورة رواتب
1. **Payroll → Pay Runs → New for period 2026-05**
2. النظام يحسب لكل موظف:
   - الراتب الأساسي + البدلات
   - حسومات GOSI 9% (موظف) + SANED 1% (سعودي فقط)
   - صافي الراتب
3. **Review** قائمة الـ payslips.
4. **Post** — يولّد قيد محاسبي + يُحضّر ملف WPS SIF.
5. **Download SIF** → ارفعه على بوابة بنكك.

### 7.3 GOSI الشهري
- **Payroll → GOSI Submissions** — التقرير الشهري للهيئة.
- يحسب: 9% موظف + 9% منشأة + 2% SANED.
- صدّر CSV / TXT بالتنسيق المطلوب.

### 7.4 نهاية الخدمة (EOS)
- يحسب تلقائياً حسب نظام العمل السعودي (المادة 84-85):
  - 1/2 شهر لكل سنة من أول 5 سنوات
  - 1 شهر لكل سنة بعد ذلك
- يظهر في قسم Provisions.

## 8. التقارير

### 8.1 P&L (قائمة الدخل)
- **Reports → P&L**
- اختر الفترة، المقارنة (M-on-M / Y-on-Y).
- صدّر PDF (ثنائي اللغة) أو Excel.

### 8.2 الميزانية (Balance Sheet)
- **Reports → Balance Sheet**
- مقياس التاريخ (As of date).

### 8.3 التدفق النقدي (Cash Flow)
- **Reports → Cash Flow**
- طريقتان: مباشرة / غير مباشرة.

### 8.4 ميزان مراجعة (Trial Balance)
- **Reports → Trial Balance**
- بكل الحسابات + الأرصدة المدينة/الدائنة.

### 8.5 AR / AP Aging
- **Reports → AR Aging** / **AP Aging**
- شرائح: 0-30, 31-60, 61-90, >90.

### 8.6 إقرار VAT
- **Reports → VAT Return**
- يولّد التقرير الفصلي بالتنسيق المطلوب من ZATCA.

## 9. الإقفال الشهري (Period Close)

```
ابدأ → تأكد:
  □ كل الفواتير المُسوّدة رُحّلت
  □ مطابقات البنوك تمّت
  □ FX Revaluation للحسابات الأجنبية
  □ القيود التسويتية موافق عليها
  □ تقرير مبدئي راجعه المدير المالي
→ Close Period
```

- بعد الإقفال، **لا يمكن** كتابة قيود في تلك الفترة.
- إذا اكتُشف خطأ بعد الإقفال، يجب إعادة فتح الفترة (تتطلب صلاحية `accounting_admin`) أو تسجيله في الفترة التالية كتسوية.

## 10. الأمان

### 10.1 المصادقة الثنائية (MFA)
- **Settings → Security → Enable MFA**
- استخدم Google Authenticator أو أي تطبيق TOTP.
- احفظ Backup codes في مكان آمن.

### 10.2 سياسة كلمات المرور
- 12 حرف على الأقل، تتضمن: حرف كبير + صغير + رقم + رمز.
- لا تُعاد دورياً (NIST guidance).

### 10.3 تسجيل الخروج التلقائي
- بعد 30 دقيقة من عدم النشاط (افتراضي).

## 11. النسخ الاحتياطي

- النسخ الاحتياطي **تلقائي** يومياً على Hetzner storage.
- لاستعادة بيانات: **Settings → Backups → Restore** (يتطلب tenant_admin).
- نسخة محلية:
  - **Settings → Export → Full Export** → ZIP فيه CSV + JSON.
