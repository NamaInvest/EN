## القواعد الذهبية لتشغيل الاختبارات الآمنة للعمليات المالية والحساسة

1. **الوقاية التامة في بيئة الإنتاج (Production Zero-Touch Policy):** يمنع كلياً محاكاة أو تشغيل أي اختبار مالي حقيقي أو تسجيل فواتير زكاة أو تأسيس قاعدة بيانات مستأجر من خلال بيئة الإنتاج الحية. أي اختبار يجب أن يتم بشكل معزول ومحلي تماماً.
2. **محاكاة الـ APIs الخارجية (Mocking Third-Party API Responses):** عند تفعيل اختبارات آلية للسيناريوهات الحساسة (مثل الزكاة والـ WPS والـ LLM)، ينبغي تحويل الطلبات إلى Mocks محلية تعيد الاستجابة الإيجابية النموذجية لحفظ استقرار العملية دون تواصل خارجي حقيقي.
3. **تطبيق الفترات المغلقة الافتراضية (Default Closed Periods):** في شاشات الجرد والتسويات، ينصح بإبقاء الفترات التاريخية مغلقة ومقيدة برمجياً في الكود، وتفعيلها فقط عند تشغيل فحص الوحدة المعزول محلياً.
4. **تجنب الهجرات المدمرة (No Destructive Database Changes):** يمنع تشغيل `prisma db push --force-reset` أو أي أوامر مسح للجداول الحية دون ترحيل واحتفاظ بالبيانات السابقة.
