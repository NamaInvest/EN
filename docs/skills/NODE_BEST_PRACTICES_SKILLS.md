# ممارسات وأمن بيئة Node.js للتطبيقات الكبرى
**المهمة:** REFERENCE_SKILLS_AND_FULL_SYSTEM_SCAN_ONLY
**المراجع:** `nodebestpractices`

يهدف هذا الدليل لترسيخ مهارات تطوير تطبيقات Node.js الخلفية والعمال (Workers) في نظام Nama Invest ERP لضمان الأمان والأداء العالي.

---

## 1. بنية التطبيق وتقسيم الطبقات (Layered Architecture)
* **القاعدة:** يجب فصل الكود إلى طبقات مستقلة: طبقة الشبكة (API / Controllers)، طبقة منطق العمل (Business Logic / Services)، وطبقة الوصول للبيانات (DataAccess / Repositories).
* **المهارة المطلوبة:**
  * عدم كتابة استعلامات قاعدة بيانات مباشرة (Prisma calls) داخل وحدات التحكم (Controllers) أو راوترات API؛ يجب نقلها لطبقة الخدمات.
  * عزل منطق التحقق من المدخلات (Input Validation) في Middleware مستقل قبل دخول طبقة العمليات.

## 2. إدارة الأخطاء والاستقرار (Resilient Error Handling)
* **القاعدة:** يجب ألا يتوقف التطبيق أو ينهار بسبب استثناء غير معالج (Uncaught Exception) أو وعود مرفوضة (Unhandled Rejection).
* **المهارة المطلوبة:**
  * استخدام كتل `try-catch` مركزية أو استخدام Middleware لالتقاط الأخطاء في إطار عمل Next.js/Express.
  * تصنيف الأخطاء إلى أخطاء تشغيلية متوقعة (Operational Errors - مثل مدخلات خاطئة، مستخدم غير مصرح) وأخطاء برمجية حرجة (Programmer Errors - مثل ReferenceError، كراش قاعدة البيانات).
  * في حال رصد خطأ برمجية حرج داخل عامل خلفي (Worker)، يجب تسجيل الخطأ وإيقاف العملية الحالية بأمان وإعادة جدولة المهمة، بدلاً من إدخال السيرفر في حلقة كراش مستمرة.

## 3. حماية الـ Event Loop وتجنب العمليات المعطلة (Non-Blocking Event Loop)
* **القاعدة:** الـ Event Loop في Node.js أحادي المسار (Single-threaded)؛ أي عملية حسابية معقدة ومتزامنة تعطل السيرفر عن خدمة الطلبات الأخرى.
* **المهارة المطلوبة:**
  * تجنب استخدام الدوال المتزامنة للتعامل مع نظام الملفات مثل `fs.readFileSync` أو `fs.writeFileSync` في مسارات الطلبات الحية؛ يفضل دائماً استخدام وعود `fs.promises`.
  * عزل العمليات الحسابية الضخمة (مثل توليد ملفات PDF، التحقق المحاسبي للقيود الضخمة، أو فحص التوقيع الرقمي للزكاة) في عمال خلفيين مستقلين (BullMQ Workers) وعدم تشغيلها مباشرة في مسار استجابة الـ HTTP Request.
