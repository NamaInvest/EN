# معايير التحقق الأمني للتطبيقات المالية والمؤسسية (ASVS)
**المهمة:** REFERENCE_SKILLS_AND_FULL_SYSTEM_SCAN_ONLY
**المراجع:** `ASVS`, `owasp-asvs-checklist`

يركز هذا الدليل على متطلبات الأمان الصارمة الخاصة بـ OWASP ASVS v4 لضمان حصانة نظام Nama Invest ERP ضد الاختراقات وتسريب البيانات بين الشركات والمستأجرين.

---

## 1. أمن وعزل المستأجرين (Tenant Isolation - ASVS V4.0.2 / V4.1)
* **القاعدة:** يجب ألا يتمكن مستخدم من مستأجر (Tenant A) من الوصول، قراءة، أو تعديل أي بيانات تخص مستأجر آخر (Tenant B) تحت أي ظرف. حدوث ذلك يعتبر خرقاً أمنياً حرجاً.
* **المهارة المطلوبة:**
  * التأكد من تمرير وفحص `tenantId` في جميع استعلامات قاعدة البيانات (Prisma Queries).
  * إخضاع كافة راوترات الـ API لحارس الصلاحيات وعزل المستأجرين `requireTenantId` أو الـ Authentication middleware المناسب.
  * عزل جلسات الكاش (Redis) وفصل عمال الخلفية (Queues) بالـ Tenant ID لمنع تداخل العمليات.

## 2. التحكم في الصلاحيات وإدارة الوصول (Access Control - ASVS V4.0.2 / V4.4)
* **القاعدة:** الالتزام بمبدأ الصلاحيات الأقل (Least Privilege) والتحقق من الصلاحيات في الخلفية (Server-side Auth) وليس الاعتماد على إخفاء الأزرار في الواجهة الأمامية فقط.
* **المهارة المطلوبة:**
  * التحقق من دور المستخدم وصلاحياته المحددة (Permissions) في الخادم عند كل طلب لتعديل البيانات أو قراءتها.
  * التحقق من الصلاحيات لكل API بشكل منفصل بدلاً من الاعتماد على التحقق العام في الـ middleware.

## 3. حماية البيانات المدخلة وتجنب الثغرات (Validation, Sanitization, & Injection Prevention - ASVS V5)
* **القاعدة:** جميع مدخلات المستخدم تعتبر غير آمنة ويجب التحقق منها وتطهيرها قبل معالجتها أو تمريرها لقاعدة البيانات.
* **المهارة المطلوبة:**
  * استخدام مكتبات تحقق صارمة مثل `Zod` للتحقق من أنواع وهياكل المدخلات في الـ APIs.
  * تجنب استخدام استعلامات SQL النصية المباشرة (Raw SQL Queries) لمنع ثغرات حقن SQL؛ يجب الاعتماد الكامل على Prisma ORM الآمن تلقائياً أو استخدام المعاملات المجهزة (Parameterized Queries) بحذر شديد.
  * تطهير وتأمين المدخلات النصية ضد ثغرات Cross-Site Scripting (XSS).

## 4. سجلات التدقيق الأمني والتعقب (Audit Logging & Traceability - ASVS V7.1)
* **القاعدة:** يجب تسجيل كافة الأحداث الأمنية والعمليات الحساسة (مثل تسجيل الدخول، تعديل الصلاحيات، العمليات المالية، الفشل في المصادقة) في سجل تدقيق غير قابل للتعديل للتكامل مع نظام SIEM.
* **المهارة المطلوبة:**
  * تسجيل هوية المستخدم، الـ Tenant ID، نوع العملية، والتوقيت بدقة.
  * حظر تسجيل أي معلومات حساسة تماماً مثل كلمات المرور، التوكنز، أو أرقام البطاقات الائتمانية في السجلات (No PII / Secret leak).

## ☑️ قائمة فحص بوابة التحقق الأمني (Security Review Gate Checklist)
- `[ ]` هل يمر كل استعلام لقاعدة البيانات من خلال فحص وحارس الـ `tenantId` الصارم؟
- `[ ]` هل يتم التحقق من الصلاحيات (Authorization) في خادم الـ API قبل البدء بمعالجة الطلب؟
- `[ ]` هل يتم استخدام مخطط تحقق صارم (مثل Zod schema) لفحص وتطهير كافة المدخلات؟
- `[ ]` هل تخلو السجلات المكتوبة بالكامل من كلمات المرور أو مفاتيح الاتصال أو معلومات المستأجر الحساسة؟
- `[ ]` هل يتم تسجيل كافة محاولات الفشل التشغيلية في الـ Audit Logs؟
