### 1. معالجة وتثبيت تجميع اختبارات TypeScript
- [ ] **إنشاء ملف `tsconfig.test.json`**:
  - إنشاء ملف تكوين مستقل ومخصص للاختبارات يوسع الملف الرئيسي `tsconfig.json`.
  - ضبط حقل `rootDir` لـ `./` لتجنب تعارض الملفات الخارجة عن مجلد المصدر `src/`.
  - تضمين مجلدات الاختبارات بالكامل `tests/**/*` و `__tests__/**/*`.
- [ ] **توطيد وتحديث `tsconfig.json`**:
  - التأكد من خلو إعدادات المترجم الرئيسي من أي تعديلات تؤثر سلباً على عملية بناء المشروع للإنتاج (Next Build).

### 2. فصل وتحديد أدوار أدوات الفحص
- [ ] **تعديل وتحديث `jest.config.ts`**:
  - ضبط وإلزام Jest بتشغيل اختبارات التكامل ومسارات الـ APIs وتفاصيل جداول قاعدة البيانات حصرياً.
  - تحديد وحصر المجلدات المستهدفة لـ Jest وتجنب فحص مجلدات اختبارات الـ Unit المعزولة.
- [ ] **تعديل وتحديث `vitest.config.ts`**:
  - ضبط وإلزام Vitest بتشغيل اختبارات الـ Unit السريعة والمحركات الحسابية المعزولة (مثل محرك GOSI والزكاة والفوترة).

### 3. حل تعارضات مكتبات الموكس والـ Imports
- [ ] **استبدال استدعاءات Jest Mocks في Vitest**:
  - فحص اختبارات Vitest المتوقفة واستبدال كافة استدعاءات `jest.fn()` بـ `vi.fn()` ودوال `vi.mock()` المخصصة لـ Vitest وتوطيد الـ global mock.
- [ ] **حل مسار ملف التدقيق `prisma-audit`**:
  - مراجعة وتصحيح استيراد ملف `prisma-audit` في ملفات اختبارات التكامل لضمان توافقه التام مع بيئة الفحص وحل مساره ديناميكياً.

### 4. توحيد وضبط أوامر تشغيل الفحوصات في `package.json`
- [ ] **تحديث الحقول داخل `package.json`**:
  - تعريف وضبط اختصارات تشغيل الفحوصات بوضوح:
    - `test:unit` (Vitest للـ Unit).
    - `test:domain` (Vitest للمحركات والزكاة والرواتب).
    - `test:integration` (Jest للتكامل والـ APIs).
    - `test:security` (Vitest لعزل المستأجرين والأمان).
    - `test:coverage` (توليد التغطية الموحد).
- [ ] **منع تشغيل اختبارات الإنتاج**:
  - وضع حظر صريح لمنع تشغيل أي اختبار يتطلب خادم إنتاج أو ربطاً حياً ببيئة الهيئات والبنوك.
