## 1. Executive Summary (الملخص التنفيذي)
نظام **Nama Invest ERP** هو نظام تخطيط موارد مؤسسات متعدد الشركات (Multi-Tenant SaaS ERP) مبني على تقنيات Next.js 16 و React 19 و Prisma 5.22 و PostgreSQL.  
بعد فحص معماري شامل للمشروع، يظهر بوضوح أن النظام متقدم للغاية في مجالات **الامتثال للأنظمة والتشريعات السعودية** (مثل ZATCA Phase 2، نظام العمل، التأمينات الاجتماعية GOSI، ونظام حماية البيانات الشخصية PDPL) ودمج تقنيات الذكاء الاصطناعي (AI CFO, AI Auditor, AI Copilot).  
ومع ذلك، توجد فجوات وظيفية وهيكلية مقارنة بالأنظمة العالمية الكبرى مثل SAP و NetSuite، لا سيما في جوانب الترابط المحاسبي الموحد (Universal Journal)، إدارة البنود المفتوحة في الحسابات المدينة والدائنة (Sub-Ledger Open Items)، وعمليات إغلاق الفترات المتقدمة. يهدف هذا التقرير إلى رسم خارطة طريق آمنة ومدروسة لسد هذه الفجوات والوصول بالنظام إلى مرحلة النضج المؤسسي الفائق (Enterprise Maturity).

## 2. Current System Map (خريطة النظام الحالية)
يتكون النظام الحالي من معمارية هجينة تدعم الويب وسحابة الـ SaaS وجهاز العميل المستقل (Electron Desktop).
- **Frontend / UI:** صفحات Next.js App Router (491 صفحة فعلية) مقسمة بين خوادم Server Components وعملاء Client Components.
- **Backend / APIs:** مسارات Next.js API Routes (848 مساراً فعلياً) محمية بواسطة `withRoute` ونظام عزل مادي لكل tenant في الـ Production (Phase 2 Database-per-tenant).
- **Core Library (`src/lib`):** يحتوي على 536 ملفاً برمجياً تشمل محركات المحاسبة التلقائية (`auto-journal.ts`)، محرك التكلفة (`costing.ts`)، ومحرك الترقيم المتسلسل (`numbering.ts`).

## 3. Existing Modules (الأقسام الموجودة)
يحتوي النظام على الأقسام المكتملة أو شبه المكتملة التالية:
1. **المحاسبة العامة (General Ledger):** شجرة حسابات متوافقة مع SOCPA، القيود اليومية التلقائية.
2. **الفوترة الإلكترونية والربط الإلكتروني (ZATCA Phase 2):**
   * **Status:** Tested and Working (تم اختبارها عملياً وتعمل بشكل ممتاز 100%)
   * **Risk Level:** Low (مستوى الخطورة: منخفض)
   * **Current Action:** Regression monitoring only (المراقبة اللاحقة لمنع التراجع فقط)
   * **الأهمية:** معتمدة ومستقرة تماماً، ومستبعدة من أي تصنيف كـ Gap أو موديول ناقص أو عائق Blocker.
   * **التوصيات الآمنة المعتمدة:**
     * اختبارات التراجع المستمرة لمنع تعطل الأكواد (Regression tests).
     * مراجعة وتدقيق سجلات العمليات والـ XML والتواقيع (Audit log review).
     * مراقبة صحة وصلاحية رموز الاستجابة السريعة (QR/XML validation monitoring).
     * متابعة الإرسال المباشر لبيئة الإنتاج الرسمية لـ Fatoora (Production submission monitoring).
     * مراجعة وإدارة معالجة الأخطاء (Error handling review).
3. **المبيعات ونقاط البيع (Sales & POS):** فلو البيع والتجزئة والمطاعم.
4. **المشتريات الأساسية (Purchases):** طلبات وأوامر الشراء وإدارة الموردين.
5. **شؤون الموظفين والرواتب (HR & Payroll):** حسابات EOS، الـ GOSI، وملفات الرواتب WPS.
6. **محركات الذكاء الاصطناعي (AI CFO & Auditor).**

## 4. Missing Modules (الأقسام الناقصة)
بالمقارنة مع SAP و Oracle NetSuite، يفتقر النظام كلياً أو شبه كلي إلى:
1. **نظام المحاسبة متعددة الكتب (Multi-Book / Multi-GAAP):** للعمل وفق معايير متعددة (IFRS + US GAAP) للشركات متعددة الجنسيات.
2. **التوحيد المالي والتسويات البينية (Consolidation & Inter-Company Eliminations):** للمجموعات القابضة.
3. **محرك حجز الكميات الفعلي في المخازن (Reservation Engine):** قبل عمليات السحب الفعلي.

---

## 5. Weak Modules (الأقسام الضعيفة)
أقسام موجودة كوداً ولكن واجهاتها أو تكاملها يحتاج نضجاً:
1. **الأصول الثابتة (Fixed Assets):** هيكلية جداولها جاهزة ومحسنة، لكن لوحات التحكم والواجهات للمستهلك النهائي ضعيفة وبسيطة.
2. **إدارة النقدية والتسويات البنكية (Treasury & Bank Recon):** خوارزمية التطابق التلقائي (Auto-matching) تحتاج تحسينات لدعم صيغ ملفات بنكية أوسع.
3. **التصنيع وحساب التكاليف (Manufacturing Standard Costing):** البنية الأساسية لـ BOM و MRP موجودة، لكن حساب انحرافات التكاليف (Variance Costing) ضعيف.

## 13. Data Flow Gaps (فجوات تدفق البيانات)

- عدم تكامل حركات الخزينة مباشرة مع نظام سداد البنود المفتوحة (Sub-ledger accounting) مما يسبب ترحيلاً نقدياً غير مرتبط بالفاتورة الأصلية مباشرة.

## 14. Security Gaps (الفجوات الأمنية)
- الحاجة إلى فرض تشفير إضافي على مستوى قاعدة البيانات لحقول أرقام الحسابات البنكية والمفاتيح السرية الحساسة.
- الحاجة إلى تفعيل التحقق الثنائي (MFA) بشكل إجباري لكافة الأدوار المحاسبية والمالية العليا.

---

## 15. Tenant Isolation Risks (مخاطر العزل بين المستأجرين)
رغم أن النظام يتبع معمارية صارمة لعزل قاعدة البيانات مادياً لكل tenant (Database-per-tenant) في خطوط الإنتاج، إلا أنه يجب التأكد من عدم تسرب أي معطيات أثناء إرسال البيانات المجمعة لوحدات الذكاء الاصطناعي المشتركة، مع فرض حواجز حماية برمجية صارمة قبل أي استدعاء خارجي.

---

## 16. Financial Integrity Risks (مخاطر السلامة المالية)
- إمكانية إجراء حركات مخزنية بأثر رجعي دون مراجعة إغلاق الفترات المالية (Period Lock) بشكل كامل.
- غياب صمامات الأمان ضد الحركات المزدوجة المتطابقة (Double Postings) على مستوى الخزينة والمصادقة.

---

## 17. Audit Logging Gaps (فجوات سجلات المراجعة)
- بالرغم من توفر سجل المراجعة، إلا أنه يسجل العمليات كلقطة كاملة للسجل، ويفتقر لواجهة مستخدم تعرض الفروقات المحددة (diff view) قبل التعديل وبعده لكل حقل محاسبي.

---

## 18. Permissions / RBAC Gaps (فجوات الصلاحيات والـ RBAC)
- الحاجة إلى تدقيق الصلاحيات للتأكد من عدم قدرة أدوار مثل `Storekeeper` على الوصول لبيانات مالية أو أسعار شراء، وفرض سياسة حظر الصلاحيات الافتراضية (Default-Deny).

---

## 19. Integration Gaps (فجوات التكامل البرمجي)
- غياب واجهات قياسية موحدة (RESTful OpenAPI Contracts) لتكامل النظام مع شبكات التجارة الإلكترونية مثل سلة وزد، أو التكامل المباشر مع منصات سداد ومدد الحكومية.

## 20. Global ERP Comparison Matrix (مصفوفة المقارنة مع الأنظمة العالمية)

## 21. Priority Ranking (ترتيب الأولويات)
1. **المرتبة الأولى (Critical):** معالجة الفجوات المحاسبية الأساسية، صمامات الأمان المالية، وحماية عزل المستأجرين (Tenant Isolation).
2. **المرتبة الثانية (High):** استكمال الصفحات غير المكتملة، وتأمين إغلاق الفترات المالية (Period Lock Governance).
3. **المرتبة الثالثة (Medium):** استكمال لوحات التحكم والتقارير المالية والتحليلية لكل قسم.

## 22. Recommended Phases (المراحل المقترحة)
* **Phase 0:** Baseline Verification (التحقق الفني الشامل لاستقرار البناء الحالي).
* **Phase 1:** UI Completion Foundation (استكمال النواقص الرسومية وإضافة شاشات الخطأ والتحميل المنظم).
* **Phase 2:** Module Dashboards (بناء لوحات المؤشرات KPIs والأنشطة لكل موديول).
* **Phase 3:** Real Data Tables & Lists (استكمال مرشحات وفلاتر الجداول وعزلها التام).
* **Phase 4:** Workflow Scenarios (تطبيق سيناريوهات العمل الكاملة).
* **Phase 5:** API Integration Hardening (تحصين وتأمين الـ APIs).

## 23. Immediate Safe Wins (المكاسب الآمنة الفورية)
- تحسين الصفحات ناقصة الواجهات أو التي تعرض Placeholder لعرض رسالة معيارية ذكية (`FeatureDisabledPanel`) توضح حالة الميزة وتمنع حدوث أخطاء واجهة مستخدم رسومية.
- إضافة شاشات تحميل مصممة باحترافية (Skeleton Loaders) وحالات الفراغ (Empty States) الجذابة لكافة الجداول واللوحات في النظام.
