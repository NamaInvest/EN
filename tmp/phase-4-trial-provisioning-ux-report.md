# تقرير المرحلة الرابعة - Trial Provisioning UX

تم بنجاح ربط واجهة الديسكتوب بخدمة الـ Backend لتمكين إنشاء بيئة عمل للشركة مباشرةً من التطبيق المكتبي، وتخزين الترخيص التجريبي بأمان للمزامنة المحلية وحساب الـ Offline Grace.

## 1. الملفات المعدلة
- `namasoft-erp-launcher/src/components/NewCompanyProvisionScreen.tsx`: إعادة صياغة الشاشة لإضافة الحقول المطلوبة (اسم المسؤول، كلمة المرور، الخ)، ومعالجة حالة الانتظار (Loading)، والنجاح، والخطأ، وحفظ الترخيص.
- `namasoft-erp-launcher/electron/types.ts`: توسيع واجهات البيانات `ProvisionTenantPayload` و `ProvisionTenantResponse` لتشمل كلمة المرور وبيانات الـ Token العائدة.
- `namasoft-erp-launcher/src/lib/api.ts`: تحديثات لتمكين استدعاء دالة `saveProvision` من الـ Renderer.
- `namasoft-erp-launcher/electron/main.ts` و `preload.ts`: كشف دالة الـ IPC `license:saveProvision`.
- `namasoft-erp-launcher/electron/licenseManager.ts`: إضافة دالة `saveProvisionedLicense` لحقن بيانات الترخيص (Token) وتواريخ הסيرفر بشكل آمن في قاعدة SQLite.

## 2. آليات التنفيذ والحماية
### كيف يتم إنشاء الشركة؟
المستخدم يكمل نموذج التسجيل (اسم الشركة، المدير، الإيميل، الجوال، كلمة المرور، الـ Subdomain). التطبيق يقوم بإرسال Payload للـ Backend عبر المسار المخصص `/api/tenant/provision`.

### كيف يتم حفظ الترخيص محلياً؟
عندما يعود السيرفر بحالة `success`، فإن استجابة الـ API ستحتوي على `trialToken, trialEndsAt, serverTime, workspaceUrl`. تقوم الواجهة فوراً باستدعاء `api.saveProvision(res)`، والتي تمر عبر الـ IPC إلى دالة `saveProvisionedLicense` داخل `licenseManager`.
تقوم الدالة بإدراج (أو تحديث) جدول `cached_license` في قاعدة البيانات المحلية. يتم وضع `status = ACTIVE`، وتحديث كل من `serverTimeAtLastVerify` و `lastSeenLocalTime` لضمان عمل نظام الـ Anti-Tamper للحماية ضد إرجاع الوقت.

### هل يتم تخزين كلمة المرور أو الـ Token في الواجهة؟
- **كلمة المرور:** لا تُخزّن نهائياً في أي مكان محلياً. تُرسل فقط للـ Backend ضمن الـ Payload أثناء الإنشاء وتختفي.
- **الـ Trial Token:** لا يُعرض أبداً للمستخدم عبر الـ UI (لا في الرابط ولا في النصوص). يخزّن فقط في قاعدة SQLite ليستخدمه التطبيق وراء الكواليس.

### كيف يتم التعامل مع الأخطاء؟
إذا قام السيرفر برفض الطلب (مثل: النطاق محجوز، البريد مستخدم مسبقاً، كلمة المرور ضعيفة)، يتم التقاط الخطأ وإظهاره بوضوح للمستخدم في واجهة بطاقة خطأ (Error Card). يمكن للمستخدم تصحيح البيانات ومحاولة الإرسال مجدداً عبر زر "إنشاء بيئة العمل".

## 3. تجربة المستخدم (UX) بعد النجاح
عند النجاح يتم إيقاف التحميل وإظهار بطاقة خضراء تؤكد النجاح، تعرض `workspaceUrl` الخاص بالشركة وتوضح أن مدة التجربة 7 أيام. يوجد داخلها زر تفاعلي **"فتح مساحة العمل"** يقوم بفتح متصفح الديسكتوب المحصن المُعدّ في Phase 3، وتوجيه المستخدم للوحة التحكم. (تم تعطيل التحويل التلقائي ليتسنى للمستخدم قراءة الرابط والتفاعل معه).
