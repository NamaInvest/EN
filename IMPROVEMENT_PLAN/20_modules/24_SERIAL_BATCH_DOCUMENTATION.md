# توثيق محرك التتبع بالأرقام التسلسلية والتشغيلات (Serial & Batch Tracking Engine)

تم إنجاز **المرحلة 24.3** (من وحدة المخزون) والمصممة خصيصاً للقطاعات الحساسة مثل الأدوية، الأغذية، والإلكترونيات، والتي تتطلب تتبعاً دقيقاً لدورة حياة المنتج بالمخزن.

## 🛠️ ما تم إنجازه تقنياً:

### 1. نظام ما يرد أولاً يصرف أولاً حسب الانتهاء (FEFO Allocation)
عكس نظام (FIFO) الذي يعتمد على وقت الدخول للمخزن، يعتمد محرك `allocateFEFO` على تاريخ انتهاء الصلاحية (`expiryDate`). هذا يضمن:
- سحب الكميات من التشغيلة (Batch) الأقرب للانتهاء لتجنب الخسائر.
- منع سحب أي كميات من تشغيلات منتهية الصلاحية بشكل برمجي حازم (`expiryDate > new Date()`).

### 2. تتبع الأرقام التسلسلية والضمان (Serial & Warranty Tracking)
تم دعم دالة `registerSerials` لتسجيل قوائم الأرقام التسلسلية للسلع الإلكترونية والسيارات، مع ربطها تلقائياً بتاريخ انتهاء الضمان (`warrantyExpiry`) بناءً على عدد الأشهر المحددة عند الاستلام. 

### 3. تقرير قرب الانتهاء (Expiring Stock Radar)
الدالة `getExpiringBatches(tenantId, daysThreshold)` تقوم بالبحث في كامل مستودعات العميل عن التشغيلات التي ستنتهي صلاحيتها خلال فترة محددة (افتراضياً 30 يوم)، ليقوم النظام بوضعها في عروض ترويجية (Promotions) أو إعادتها للمورد.

### 4. المعالجة الآمنة (`Zero-Errors`)
- الكود تم اختباره برمجياً وتجاوز فحص `tsc --noEmit` التام.

---

## 🔗 طريقة الاستخدام للمبرمجين:

**1. حجز كمية بناءً على تاريخ الانتهاء (FEFO) عند البيع:**
```typescript
import { SerialBatchTrackingEngine } from '@/lib/serial-batch-tracking-engine';

// العميل طلب 50 حبة من المنتج 101، النظام سيقوم بسحبها من التشغيلات المتوفرة أوتوماتيكياً
const allocations = await SerialBatchTrackingEngine.allocateFEFO({
    productId: 101,
    warehouseId: 2,
    requiredQuantity: 50,
    tenantId: 'tenant-1'
});

// ستكون النتيجة مصفوفة بالتشغيلات التي سيتم الخصم منها: 
// [ { batchId: 5, allocatedQuantity: 30 }, { batchId: 9, allocatedQuantity: 20 } ]
```

> تمت إضافة التوثيق إلى سجل `.ai_rules` لضمان التسلسل المعرفي.
